# 111. CounterGhost — Distributed Counter Integrity After Partial Node State Loss

**111. CounterGhost — Distributed Counter Integrity After Partial Node State Loss**
**Problem Statement**
A counter sharded across multiple nodes for scalability, such as tracking remaining inventory or requests against a rate limit, depends on periodically aggregating each node's local count into a trustworthy global total, but if a node crashes and restarts having lost part of its local counter state, the global aggregate can be silently undercounted in a way that looks identical to a normal counter reset, causing the system to allow more requests or reservations than the true global limit actually permits. Design a system that manages simulated sharded counters across nodes subject to realistic partial state loss on crash, and correctly distinguishes a genuine partial state loss from a normal reset, recovering an accurate global count rather than silently undercounting. A convincing demonstration should crash a node with partial local counter loss, and show the system correctly detecting and correcting the resulting global count rather than accepting the undercount. After restart, delayed pre-crash counter deltas may arrive again; recovery must use durable delta identity or equivalent evidence to restore the exact global count without either losing the missing contribution or double-counting replayed deltas.
